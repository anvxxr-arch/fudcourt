# Data Catalog (Phase 1)

One row per **major dataset actually present in the repository**, ordered by domain.
Every row names the layer the dataset occupies **today** (not where it should go), the
provider-shaped carrier by file+symbol, and the exact reader paths.

> **Canonical vocabulary is borrowed from `docs/architecture/canonical-model.md`**
> (§2 "Canonical entity list", §3 "Domain taxonomy"). Entity names (`Asset`, `Token`,
> `Chain`, `Venue`, `Instrument`, `Price`, `Candle`, `Protocol`, `Pool`, `Account`,
> `Balance`, `Position`, `Order`, `Fill`, `Execution`, `Transaction`, `LedgerEntry`,
> `Signal`, `NewsArticle`) and owner assignments (`[removed: finance/ledger]`,
> `[removed: markets/instruments]`, `apps/executor/internal/orders`, …)
> are that document's. Where this catalog had to assume a name or owner it says so inline
> and the row is repeated in **§16 Rows requiring reconciliation**.
>
> Scope: task brief supplied to this audit; not stored in-repo. Originating session
> transcript: `history://source-inventory`. **Path note:** all paths are post-move
> (`apps/data/internal/research/*`, `apps/data/platform/*`,
> `apps/api/internal/{markets/{instruments,overview},finance/*,accounts/*,access/*}`),
> each verified with `test -f`.

**Layer legend (canonical-model.md §1):** `RAW` bytes as received · `PARSED` typed, still
upstream-shaped · `NORMALIZED` this repo's names/units, still per-provider · `CANONICAL`
provider-neutral + minted id · `ENRICHED` canonical ⋈ canonical · `DERIVED` computed ·
`PRODUCT_VIEW` the wire envelope a route returns.

**Time semantics (canonical-model.md §4.1):** `occurred_at` (world) / `observed_at` (we
looked) / `received_at` (payload reached us) / `recorded_at` (row written) / `updated_at`
(last mutation). The column quotes the *actual* field/column names; `✗` marks a category
with no carrier in the tree.

**Identifier rule (canonical-model.md D-CANON):** symbols are **not** identity; a canonical
id is a stable opaque string with a `(provider, provider_id) → canonical_id` mapping.
D-CANON records that **no such mapping table exists anywhere in the repo**, so every
"identifier strategy" below is the de-facto key, not a canonical id.

## 10. Cross-cutting catalog notes

1. **Five datasets inherit a fully-shaped canonical model** — Instrument, Order, Fill,
   Execution, and the sealed credential envelope. Everything else stops at NORMALIZED
   (per-provider) or jumps straight to SQL.
2. **The most repeated defect is symbol-as-identity**: `Asset`, `Chain`, `Venue`, `Price`,
   `Balance`, `Signal`, `NewsArticle` all key on provider strings, and two SQL tables bake it
   into a unique constraint (`price_history`, `asset_history`).
3. **Two datasets write straight through to SQL with no canonical step**: `assets` (Rust sync)
   and `transactions` (Next route). Their "canonical representation" is the SQL DDL, not a model.
4. **Five tables have storage but no producer** (`price_history`, `journal`, `ledger`, `trades`,
   `accounts`) and one has a producer but no id space (`assets`).
5. **`[INFERENCE]` rows**: treasury table writers, `[removed: finance/ledger]` and `[removed: finance/treasury]` route
   wiring, `asset_history` consumers, Hyperliquid spot label shape, and the `audit_logs` TS/Go
   record equivalence.
