| **The CoinAnk boards were never paywalled — `{"success":false,"code":"403","msg":"please sub api to get data"}` is a SELF-CLEARING refusal, and the fetcher was treating the first attempt as final.** Symptom: `monitor.py` reported four FAILs (coinank `etf`/`whales`/`liquidations`/`fundingRate` all 502 at the BFF) and the boards reading them (`/funding`, `/etf`, `/whales`, the long/short and liquidation halves of `/derivatives`) had no data. The first hypothesis — CoinAnk put these endpoints behind a subscription — was **WRONG, and disproven three ways before any code was written**: (a) a garbage, empty or absent signature answers a DIFFERENT message (`system error`), so the client-side signature in `sign.go` is ACCEPTED and the gate is downstream of it; (b) the live dashboard still ships the same bundle constants — same uuid `b2d903dd-…`, same `+2222222222222` offset, same `347` suffix, same `web-version 102` — so the algorithm had not rotated; (c) seconds later every mode returned `success:true` with full real payloads (`fundingRate` **1,866,361 B**, `longShort` 165,560 B, `etf` 472,678 B) on the same host with the same headers. Version was not the gate either: 1, 102, 103 and 104 all answer identically. The refusal is a burst/abuse heuristic of theirs, and one this family can **induce itself** — it appeared while a recon script was firing 60 requests back to back, which is why the retry added here is backed off rather than tight. Root cause: `fetch()` had **no retry at all**, so a blip that clears in a second became a `HardError` on attempt 1 and blanked the board. A second, quieter defect sat next to it: `writeCache` ran BEFORE `Decode`, so a refused envelope (`success:false`) was written to the disk cache as if it were data — survivable, because a warm read re-decodes, fails and falls through to a re-fetch, but it wasted one of the 64 slots and left a body on disk no reader would ever accept. The fix is a bounded, class-aware retry (3 attempts, 700 ms then 1400 ms backoff) where **only** the transient classes retry — the measured refusal message, transport errors, 429 and 5xx — while `code:"0"` / `system error!` (a deterministic missing/unsupported param) and any other 4xx fail immediately, so the retry can never become a timeout-burner; a cancelled context is not a blip and does not retry either. Each attempt **re-signs**, because the signature is derived from the millisecond clock and replaying attempt 1's headers would fail a second time for a new reason.
