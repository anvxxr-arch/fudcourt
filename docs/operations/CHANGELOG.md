A wrong or missing signature is **not** a 401: upstream answers **HTTP 200 `{"success":false,"code":"500","msg":"system error!"}`**, so the failure mode is a confident empty table unless the envelope is read — the handler therefore surfaces upstream's own refusal as a **502 carrying its code and message**, never a 200 with an empty table. The signature was reconstructed from the bundle and then verified INDEPENDENTLY: the verifier re-derives it in Python and fetches all five upstreams itself, so the adapter's row counts are compared against a **direct fetch** rather than against themselves (881 / 10 / 716 / 704 / 50 rows on the last run). **The interval trap is why the allowlist exists:** `interval` accepts only `1h,2h,4h,6h,12h,1d`; `8h` — and `24h`/`7d`/`30d` — are answered by upstream with a **`success:true` ALL-ZERO table** (`totalTurnover:0`), measured live, so a pass-through route would render a fabricated zero as data; out-of-allowlist values are refused locally with **400 `invalid param`** naming the accepted set and the reason, and the five accepted intervals were each confirmed to carry real turnover (1h 13.4M … 1d 323.3M).
